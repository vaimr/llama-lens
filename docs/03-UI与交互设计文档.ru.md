|---|---|---|---|---|---|

- Форма bar-карт: крупная цифра (24px count-up) + горизонтальная полоса + деления 0/середина/полный + sparkline за 60с (1.2px постоянная толщина) + нижняя строка пик/мин/среднее за 60с
- Полный масштаб полос: карты скорости динамический (пик за 60с × 1.1, округление до 1/2/2.5/5×10^n, минимум 10); карты контекста фиксированный ctx.total (деления 0/середина/полный в k-формате)
- Форма прибора: ECharts gauge (240° дуга, 12px трек, цветовые зоны порогов, основные/вторичные деления, тонкая стрелка + якорь), центральная крупная цифра 300ms count-up
- Цветовая зона MTP обратная (0-65 красный / 65-80 жёлтый / 80-100 зелёный, низ = плохо); цвет по значку задаётся zoneColors (источник тех же порогов, что и зона)
- Нет данных (llama оффлайн / нет задач): полоса на ноль, цифра «—» серым, тренд скрыт
- Сетка: >1500px 4 колонки; ≤1500px 2 колонки; ≤640px 1 колонка

### 3.4 Область задач генерации в реальном времени (LlamaStateCard + EventFeed)

- Двухколоночный макет (640px + 1fr), обе карты с фиксированной высотой 320px (`.task-row > * { height: 320px }`): слева LlamaStateCard отвечает «чем llama сейчас занимается» (спецификация полей §3.5), при переполнении — скролл внутри карты (overflow-y: auto); справа EventFeed (fill-режим, §3.11)
- Цель фиксированной высоты: разные фазы (idle/prompt/generation) имеют разную высоту контента, предотвращение скачков макета
- ≤1500px возврат к 1 колонке (обе карты всё ещё по 320px)

### 3.5 LlamaStateCard (карта текущего статуса)

- Шапка: бейдж фазы + бейдж реал.времени логов + справа «работает» (now - state.started_at, обновляется каждую секунду по снимку)
- Три колонки крупных статистических ячеек (stat3, динамические значения):
  - При генерации: декодировано (растёт) / скорость реал.времени 3s (колеблется) / среднее по задаче
  - Обработка Prompt: скорость Prompt / обработано Prompt (n_prompt_tokens_processed, растёт) / затраченное время (prompt_elapsed_s)
- Полоса прогресса: префилл = прогресс prompt; генерация = n_decoded/(n_decoded+n_remain) (показывается только если n_remain>0, т.е. установлен лимит)
- При генерации: ETA завершения (n_remain ÷ tg_3s, только n_remain>0) + две колонки kv (занятость контекста / MTP принятие (log.mtp, обновление task_end, <65 красный / 65-80 жёлтый / ≥80 зелёный, с accepted/generated) / оставшиеся токены (n_remain, -1 показывает «без лимита») / всего prompt / попадание кэша / повторное использование Graphs (log.graphs_reused))
- При обработке Prompt: полоса прогресса + две колонки kv (всего prompt / ETA оставшееся / занятость контекста / попадание KV кэша)
- В простое: занятость контекста + сводка предыдущей задачи (токены/средняя скорость/MTP) + две колонки kv (всего затраченное время / время префилла@скорость / время генерации / повторное использование Graphs)
- Нижняя полоса конфигурации (cfg-strip, из process.flags статическая конфигурация): Spec декодирование (spec_type×spec_draft_n_max) / KV кэш (cache_type_k/v) / размер батча (batch/ubatch) / слои GPU
- Задача #id, is_child, slot id/всего (активные слоты / всего слотов)
- Данные: log.state.* (включая started_at) / log.context (used/total/pct) / log.mtp (acceptance/accepted/generated) / log.graphs_reused / активный slot (is_processing: id, n_prompt_tokens, n_prompt_tokens_cache → попадание кэша = cache/total, n_prompt_tokens_processed, n_remain) / process.flags
- MTP принятие, отображаемое при генерации, — значение предыдущей задачи (log.mtp обновляется только task_end, тот же источник, что и прибор на панели обзора)

| Правая | Сетка 3×4 компактная (kv 11px): температура / температура видеопамяти / энергопотребление (draw/limit) / загрузка видеопамяти / вентилятор / частота (графика/видеопамять) / PCIe (gen x width) / P-State / статус downclocking (битовая маска → короткое имя на китайском, 0=нормально) / ECC (исправлено/неисправлено) / версия CUDA / версия драйвера | Температура ≥75 жёлтый ≥85 красный; энергопотребление ≥85% жёлтый ≥95% красный; ECC неисправлено >0 красный; downclock активен жёлтый |
| Низ | Список процессов, использующих GPU (pid name mem) | — |

### 3.7 Системная область

- CpuPanel: крупная цифра整机 % + 6 вертикальных столбцов (каждое ядро, высота=загрузка, градиент голубой→красный) + load 1/5/15 + частота; порог ≥80 жёлтый ≥90 красный
- MemPanel: крупная цифра used/total + три полосы (used / buff_cache / available стеком) + swap; порог ≥85 жёлтый ≥95 красный
- DiskPanel: полоса на точку монтирования (mount, used/total, %) + скорости чтения/записи; порог ≥80 жёлтый ≥90 красный
- NetPanel: скорость rx/tx на каждую сетевую карту + мини-график за 60с

### 3.8 Область процессов

- LlamaProcessCard:
  - Первая строка: сетка из 4 колонок (7 элементов, раскладка 4+3): PID | CPU реал.время% (крупная цифра) | Кумулятивный CPU% | RSS | VSZ | Потоки | Время работы
  - Вторая строка: systemd ключ-значение (метка слева, значение справа, 5 строк): юнит службы · active / время запуска / кумулятивный CPU службы / память службы (включая пик) / Задачи
  - Командная строка: моноширинный шрифт, развёрнута по умолчанию (pre-wrap, можно кликнуть для сворачивания)
  - Таблица параметров: трёхколоночная сетка (имя параметра → значение), 20+ элементов, сворачиваемая (развёрнута по умолчанию)
- TopProcessTable: две таблицы (Top CPU / Top память), по 8 строк: pid name cpu% mem% rss (PID и числовые колонки выровнены по правому краю, длинные имена процессов обрезаются многоточием, при наведении показывается полное имя)

### 3.9 Область модели и Slot

- ModelInfoCard: сетка ключ-значение (имя/путь/ftype/параметры/объём файла/mmproj/векторное измерение/словарь/контекст/модальность/capabilities/owned_by)
- SlotTable:
  - Шапка: Slot {id} · {работает/ожидание} · задача #{id_task}
  - Токены prompt: всего / обработано / кэш (3 числа)
  - Декодировано / осталось / полоса занятости контекста
  - Производные из логов: прогресс prompt (log), итоги по времени задачи (prompt/decode/общее время и скорость), MTP принятие, KV retain f_keep
  - Таблица параметров сэмплирования (сворачиваемая, по умолчанию temperature/top_k/top_p/min_p/max_tokens/chat_format/speculative.types, полная 30+ элементов можно развернуть)

### 3.10 Область трендов (TrendChart × 12, 3 группы)

### 3.11 Поток событий (EventFeed)

- Позиция: правая карта в области задач генерации (fill-режим, фиксированная высота 320px, feed-box flex:1 + overflow-y: auto, при переполнении — полоса прокрутки); ≤1500px возврат к 1 колонке — всё ещё фиксированная 320px
- Стиль терминала: моноширинный шрифт, тёмный фон, окраска бейджей уровня [INFO] зелёный / [WARN] жёлтый / [ERROR] красный
- Источники событий: бэкенд EventDetector (преимущественно строки логов): начало задачи (ID задачи / количество токенов prompt), начало префилла (всего токенов prompt), конец задачи (всего токенов / время / средняя скорость / MTP принятие / занятость контекста), пересечение порогов (alert: метрика значение ≥/≤ порог (warning/danger) / возврат к норме, минимальный интервал между двумя событиями одного metric — 30с), запуск (модель загружена / boot-информация), онлайн/оффлайн
- Автопрокрутка: при нахождении пользователя внизу — следование за новыми событиями; после прокрутки вверх — кнопка «↓ Новые события»
- Хранить 200 записей, более ранние — затухают
